# Phil's voice

1. Read `~/Vaults/Memory/system/phil-writing-style.md` and follow it. Pick the matching pattern and language.
2. Facts first. Use only facts from the conversation, repo, data or Phil. Missing fact the draft needs: ask Phil for exactly that fact. Never invent figures, names, dates or approvals.
3. Draft, then check every line against the Core rules and the Never list. Fix violations before showing the draft.
4. Deliver the draft in one fenced block, ready to paste. Teams and email: plain lines and simple lists, no Markdown headers. Below the block, list only unverified facts or a register flagged under Gaps.
5. Post or send only when Phil asked for it.

## Edit loop

When Phil rewrites a draft or says what was wrong:

1. Compare his version with yours and name the general rule behind each change. Skip one-off content edits.
2. Append each rule under `## Corrections` in the style file: `YYYY-MM-DD: rule. before → after`.
3. A rule that repeats an existing correction: move it into the matching section and delete the duplicate entries.
4. Tell Phil in one line what you recorded.
